## 第七章：智能指针与并发

### ① 核心概念

**一句话总结：**
> 智能指针是"带附加行为的指针"，Rust 通过它们实现堆分配（Box）、共享所有权（Rc/Arc）、内部可变性（Cell/RefCell）；并发安全由**类型系统**保证——编译器通过 Send/Sync 特征自动检查你的类型是否能安全地跨线程使用。

**生活类比：**
- **Box<T>** = 快递包裹——你把东西放进盒子里（堆上），盒子离开你家（作用域）时自动扔掉（释放）
- **Rc<T>** = 一本多人共有的书——几个人同时读，没有人是唯一主人，全部人读完才回收
- **Arc<T>** = 一个多人共有的、可以跨房间（线程）传阅的书——和 Rc 类似但线程安全
- **RefCell<T>** = 一个带监控的保险箱——平时只允许查看（不可变借用），但管理员可以打开修改（可变借用），违反规则会触发警报（panic）
- **Mutex<T>** = 一个会议室——一次只能进一个人（线程），进去锁门，出来开门

**用 C 的视角理解：**

| 智能指针 | C 中的对应 | 关键差异 |
|---------|-----------|---------|
| `Box::new(x)` | `malloc(sizeof(T))` + 赋值 | 自动 `free`，编译期检查 |
| `Rc::clone()` | 手动引用计数 | 自动维护计数，但非线程安全 |
| `Arc::clone()` | 原子引用计数 | 线程安全，性能略低 |
| `RefCell<T>` | 无直接对应 | 运行时借用检查，类似关掉编译器检查 |
| `Mutex<T>` | `pthread_mutex_t` + 数据 | Mutex 包裹了数据，保证锁和数据绑定 |
| `Cell<T>` | 无 | 栈上的内部可变性，零开销 |

### ② 为什么需要它？

**解决什么痛点？**

1. **编译时借用检查太严格**：某些模式（如双向链表、观察者模式）在编译时无法验证安全性，需要运行时检查——`RefCell` 提供了"运行时借用检查"
2. **共享所有权**：树/图中一个节点被多个父节点引用，谁应该是"所有者"？——`Rc` 允许引用计数的共享所有权
3. **线程安全的数据共享**：多个线程需要同时访问同一份数据——`Arc<Mutex<T>>` 是标准方案
4. **Deref 强制转换**：智能指针可以"透明地"像普通引用一样使用——`Box<T>` 可以调用 `T` 的方法

**Rust 并发模型的独特之处：**

```
C 中的并发问题：
  线程 A: 读取 shared_data
  线程 B: 写入 shared_data
  结果：数据竞争（未定义行为）
  修复：程序员手动加锁（容易忘）

Rust 中的并发问题：
  fn main() {
      let data = Rc::new(0);
      thread::spawn(move || {  // 编译错误！Rc 不是 Send
          println!("{}", data);
      });
  }
  结果：编译器拒绝编译，不需要加锁！
  修复：改用 Arc（线程安全的引用计数）
```

### ③ 精简代码示例

**Box<T>——堆分配和递归类型：**

```rust
// 递归类型：链表中的一个元素包含另一个元素
// 如果不用 Box，编译期无法确定 List 的大小
enum List {
    Cons(i32, Box<List>),  // Box 是堆上的指针，大小固定
    Nil,
}

fn main() {
    let list = Cons(1, 
        Box::new(Cons(2, 
            Box::new(Cons(3, 
                Box::new(Nil))))));
    
    // Box 像普通值一样使用
    let x = Box::new(5);
    println!("{}", x);          // 自动解引用，输出 5
    println!("{}", *x);         // 显式解引用
    println!("{}", *x + 2);     // 7
    
    // Box 的主要用途：
    // 1. 递归类型（如上）
    // 2. 在堆上分配大对象（避免栈溢出）
    // 3. 不关心大小，只想要一个指针
    // 4. trait object: Box<dyn Trait>
    
    // Deref 强制转换
    fn print_str(s: &str) {
        println!("{}", s);
    }
    let s = Box::new(String::from("hello"));
    print_str(&s);  // &Box<String> → &String → &str（自动转换）
}
```

**Deref 和 Drop trait——智能指针的两个核心特征：**

```rust
use std::ops::Deref;

// 自定义智能指针
struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}

// 实现 Deref 使得 * 解引用可用
impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T {
        &self.0
    }
}

// Drop trait——值离开作用域时自动调用
impl<T> Drop for MyBox<T> {
    fn drop(&mut self) {
        println!("MyBox 被释放了");
    }
}

fn main() {
    let x = MyBox::new(5);
    println!("{}", *x);  // 解引用，输出 5
    
    // Drop 在作用域结束时自动调用
    // 但如果想提前释放，可以 drop(x);  // std::mem::drop(x);
    // 注意：不能直接调用 x.drop()（会被编译器阻止，防止双重释放）
}
```

**Rc<T>——单线程引用计数：**

```rust
use std::rc::Rc;

// 用 Rc 实现共享链表节点
#[derive(Debug)]
enum List {
    Cons(i32, Rc<List>),
    Nil,
}

use List::{Cons, Nil};

fn main() {
    // Rc::new 创建引用计数为 1 的值
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    println!("a 的引用计数: {}", Rc::strong_count(&a));  // 1
    
    // Rc::clone 增加引用计数（注意：不是深拷贝，只是增加计数）
    let b = Cons(3, Rc::clone(&a));  // 引用计数 +1
    println!("a 的引用计数: {}", Rc::strong_count(&a));  // 2
    
    {
        let c = Cons(4, Rc::clone(&a));
        println!("a 的引用计数: {}", Rc::strong_count(&a));  // 3
    }
    // c 离开作用域，引用计数 -1
    println!("a 的引用计数: {}", Rc::strong_count(&a));  // 2
    
    // 引用计数为 0 时，数据自动释放
    // 注意：Rc 只能在同一线程中使用
}
```

**RefCell<T>——内部可变性（运行时借用检查）：**

```rust
use std::cell::RefCell;

fn main() {
    // RefCell 允许在"不可变引用"内部修改值
    // 借用规则在运行时检查（违反则 panic，不是编译错误）
    
    let data = RefCell::new(5);
    
    // 修改 RefCell 中的值
    {
        let mut mut_ref = data.borrow_mut();  // 运行时可变借用
        *mut_ref += 1;
    }  // mut_ref 离开作用域，借用结束
    
    let immut_ref = data.borrow();  // 运行时不可变借用
    println!("{}", *immut_ref);  // 6
    // immut_ref 离开作用域，借用结束
    
    // 运行时借用违规（会 panic）：
    // let m1 = data.borrow_mut();
    // let m2 = data.borrow_mut();  // 运行时 panic！
    // thread 'main' panicked at 'already borrowed: BorrowMutError'
}

// 经典用法：Rc<RefCell<T>>——共享 + 可变
use std::rc::Rc;
use std::cell::RefCell;

#[derive(Debug)]
enum List {
    Cons(Rc<RefCell<i32>>, Rc<List>),
    Nil,
}

use List::{Cons as ListCons, Nil as ListNil};

fn list_example() {
    let value = Rc::new(RefCell::new(5));
    
    let a = Rc::new(ListCons(
        Rc::clone(&value),
        Rc::new(ListNil),
    ));
    
    let b = ListCons(Rc::new(RefCell::new(6)), Rc::clone(&a));
    let c = ListCons(Rc::new(RefCell::new(7)), Rc::clone(&a));
    
    // 通过 value 修改所有共享的值
    *value.borrow_mut() += 10;  // value 变成 15
    
    println!("a 现在是: {:?}", a);  // Cons(RefCell { value: 15 }, Nil)
}
```

**Cell<T>——栈上的内部可变性（零开销）：**

```rust
use std::cell::Cell;

fn main() {
    // Cell 是 RefCell 的"轻量版"
    // 适用于 Copy 类型的内部可变性
    // 零运行时开销（不需要借用检查）
    
    let x = Cell::new(5);
    println!("{}", x.get());  // 5
    
    x.set(10);
    println!("{}", x.get());  // 10
    
    // Cell vs RefCell：
    // Cell：只适用于 Copy 类型，不用借用规则，零开销
    // RefCell：适用于所有类型，运行时借用检查，有少量开销
}

// Cell 的实际应用场景
struct Counter {
    count: Cell<i32>,
}

impl Counter {
    fn new() -> Self {
        Counter { count: Cell::new(0) }
    }
    
    fn increment(&self) {  // 注意：&self 是不可变引用！
        self.count.set(self.count.get() + 1);  // 但可以修改内部值
    }
    
    fn value(&self) -> i32 {
        self.count.get()
    }
}
```

**Arc<Mutex<T>>——多线程并发：**

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    // 创建被互斥锁保护的计数器
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];
    
    for _ in 0..10 {
        let counter = Arc::clone(&counter);  // 增加 Arc 引用计数
        let handle = thread::spawn(move || {
            // lock() 返回 MutexGuard，离开作用域自动解锁
            let mut num = counter.lock().unwrap();
            *num += 1;
            // 锁在这里自动释放
        });
        handles.push(handle);
    }
    
    // 等待所有线程完成
    for handle in handles {
        handle.join().unwrap();
    }
    
    println!("最终结果: {}", *counter.lock().unwrap());  // 10
}
```

**RwLock<T>——读写锁：**

```rust
use std::sync::{Arc, RwLock};
use std::thread;

fn main() {
    // RwLock：多个读，单写（比 Mutex 更适合读多写少的场景）
    let data = Arc::new(RwLock::new(5));
    let mut handles = vec![];
    
    // 多个读线程
    for i in 0..5 {
        let data = Arc::clone(&data);
        handles.push(thread::spawn(move || {
            let read = data.read().unwrap();
            println!("读线程 {}: {}", i, *read);
            // 读锁自动释放
        }));
    }
    
    // 一个写线程
    let data_write = Arc::clone(&data);
    handles.push(thread::spawn(move || {
        let mut write = data_write.write().unwrap();
        *write += 10;
        println!("写线程完成");
    }));
    
    for h in handles {
        h.join().unwrap();
    }
}
```

**线程间通信（Channel）：**

```rust
use std::sync::mpsc;  // multi-producer, single-consumer
use std::thread;
use std::time::Duration;

fn main() {
    // 创建通道
    let (tx, rx) = mpsc::channel();
    
    // 发送端（可以在多个线程复制 tx）
    let tx1 = tx.clone();
    thread::spawn(move || {
        let vals = vec![
            String::from("你好"),
            String::from("来自"),
            String::from("线程 1"),
        ];
        for val in vals {
            tx1.send(val).unwrap();
            thread::sleep(Duration::from_millis(200));
        }
    });
    
    thread::spawn(move || {
        let vals = vec![
            String::from("这是"),
            String::from("线程 2"),
        ];
        for val in vals {
            tx.send(val).unwrap();
            thread::sleep(Duration::from_millis(300));
        }
    });
    
    // 接收端（主线程）
    for received in rx {
        println!("收到: {}", received);
    }
    // 当所有发送端关闭后，for 循环结束
}
```

**Send 和 Sync——Rust 的并发安全特征：**

```rust
// Send：类型可以跨线程转移所有权
// Sync：类型可以被多个线程共享引用（&T 是 Send 的）

// 标准库中的定义：
// unsafe trait Send {}
// unsafe trait Sync {}

// 自动实现：
// - 几乎所有基本类型都实现了 Send 和 Sync
// - 完全由 Send + Sync 类型组成的类型也自动实现

// 没有实现 Send 的例子：
// - Rc<T>（引用计数不是原子的）
// - *const T / *mut T（裸指针）

// 没有实现 Sync 的例子：
// - RefCell<T>（运行时借用检查不是线程安全的）
// - Rc<T>

// 已经实现 Send + Sync 的：
// - Arc<T>（原子引用计数）
// - Mutex<T>
// - RwLock<T>

// 手动实现 Send/Sync 需要 unsafe，99% 的情况不需要
unsafe trait Send {}
unsafe trait Sync {}
```

**Atomic 类型——无锁并发：**

```rust
use std::sync::atomic::{AtomicI32, Ordering};
use std::sync::Arc;
use std::thread;

fn main() {
    // Atomic 类型比 Mutex 更轻量，适用于简单的计数器场景
    let counter = Arc::new(AtomicI32::new(0));
    let mut handles = vec![];
    
    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        handles.push(thread::spawn(move || {
            // fetch_add：原子的加法操作
            counter.fetch_add(1, Ordering::SeqCst);
        }));
    }
    
    for h in handles {
        h.join().unwrap();
    }
    
    println!("结果: {}", counter.load(Ordering::SeqCst));  // 10
}
```

**关键点说明：**

| 智能指针 | 线程安全 | 借用检查时机 | 用途 |
|---------|---------|------------|------|
| `Box<T>` | 是 | 编译时 | 堆分配、递归类型、trait object |
| `Rc<T>` | 否 | 编译时 | 单线程共享所有权 |
| `RefCell<T>` | 否 | **运行时** | 单线程内部可变性 |
| `Cell<T>` | 否 | 无 | 单线程 Copy 类型内部可变性 |
| `Rc<RefCell<T>>` | 否 | 运行时 | 单线程共享 + 可变 |
| `Arc<T>` | 是 | 编译时 | 多线程共享所有权 |
| `Mutex<T>` | 是 | 运行时 | 多线程互斥访问 |
| `Arc<Mutex<T>>` | 是 | 运行时 | 多线程共享 + 可变 |
| `AtomicI32` 等 | 是 | 无 | 无锁并发 |
