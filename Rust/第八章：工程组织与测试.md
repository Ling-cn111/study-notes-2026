## 第八章：工程组织与测试

### ① 核心概念

**一句话总结：**
> Rust 的工程组织以**模块（mod）** 和**包（crate）** 为核心，`cargo test` 提供了一流的测试支持（单元测试、集成测试、文档测试三合一），文档注释中的代码块自动变成测试——保证示例代码永远正确。

**生活类比：**
- **模块（mod）** = 公司里的部门（销售部、研发部、财务部），每个部门有自己的职责和内部信息
- **包（crate）** = 一家公司，对外提供产品（库）或直接面对客户（可执行文件）
- **workspace** = 集团公司，下面管理多家子公司（多个 crate）
- **pub** 可见性 = 部门对外的窗口——有些信息公司内部都能看（`pub(crate)`），有些对外公开（`pub`）
- **测试** = QA 质检员，确保产品不出 Bug——等级分三级：单元测试（自测）、集成测试（联调）、文档测试（说明书验证）

**用 C 的视角理解：**

| Rust 概念 | C 中的对应 | 关键优势 |
|-----------|-----------|---------|
| `mod` 模块 | `.h` 头文件 | 自动文件映射，没有 `#ifndef` 问题 |
| `use` | `#include` | 有路径概念，不会污染命名空间 |
| `pub` 可见性 | `extern` / `static` | 更精细的控制（`pub(crate)`、`pub(super)`） |
| `crate` | `.a` / `.so` / 可执行文件 | 统一构建系统 |
| `cargo test` | Makefile 中集成的测试 | 原生支持，三种测试类型 |
| `#[derive]` | 无 | 自动实现 trait |

**Rust 中的"模块查找"规则：**

```
mod math;          // 查找 math.rs 或 math/mod.rs
mod math {
    // 内联模块
}
```

```
项目结构：
src/
├── lib.rs         → crate 根
├── math.rs        → mod math;
└── math/
    ├── mod.rs     → 等价于 math.rs
    └── algebra.rs → math 模块的子模块：mod algebra;
```

### ② 为什么需要它？

**解决什么痛点？**

1. **头文件地狱**：C 中 `.h` 文件的管理非常繁琐——`#ifndef` / `#pragma once`、循环依赖、顺序问题
2. **作用域污染**：C 的 `#include` 是文本复制，所有内容直接注入当前作用域——命名冲突是常见问题
3. **测试零散**：C 项目没有官方测试框架——需要自己集成 CUnit、Check、Google Test，配置复杂
4. **文档和代码脱节**：文档中的示例代码常常无法编译，没人知道——Rust 的文档测试确保示例代码可编译可运行
5. **构建脚本缺失**：C 项目在编译前可能需要生成代码、编译 C 代码——Rust 用 `build.rs` 解决

**Rust 的方案：**

| 特性 | 解决的问题 | 使用方式 |
|------|-----------|---------|
| 模块系统 | 代码组织 + 可见性控制 | `mod` + `use` + `pub` |
| 单元测试 | 函数级别的白盒测试 | `#[cfg(test)] mod tests { ... }` |
| 集成测试 | crate 级别的黑盒测试 | `tests/` 目录下的文件 |
| 文档测试 | 确保文档示例代码正确 | `///` 注释中的代码块 |
| `#[derive]` | 自动实现常用 trait | `#[derive(Debug, Clone)]` |
| `build.rs` | 编译前自定义操作 | 在构建前运行 Rust 脚本 |
| feature flags | 条件编译的特性开关 | `Cargo.toml` 中的 `[features]` |
| workspace | 多 crate 管理 | 根 `Cargo.toml` 中 `[workspace]` |

**可见性控制详解：**

```rust
// 可见性修饰符
fn private_fn() {}               // 默认私有，仅当前模块可见

pub fn public_fn() {}            // 全部可见

pub(crate) fn crate_visible() {} // 仅当前 crate 内部可见

pub(super) fn parent_visible() {}// 仅父模块可见

pub(in crate::some::module) fn restricted() {}  // 仅指定模块可见

// 实战中的可见性设计模式
mod database {
    // 公开给外部使用的 API
    pub fn connect() -> Connection { /* ... */ }
    
    // crate 内部使用（不对外暴露）
    pub(crate) fn run_migration() { /* ... */ }
    
    // 内部实现细节
    fn parse_config() -> Config { /* ... */ }
}

// 使用
use database::connect;
// database::run_migration();   // 如果在另一个 crate，编译错误
```

**use 的各种写法：**

```rust
// ===== 基础 use =====
use std::collections::HashMap;           // 直接导入
use std::collections::BTreeMap;          // 同上

// ===== 嵌套路径 =====
use std::collections::{HashMap, BTreeMap};  // 同上，但一行

// ===== 别名 =====
use std::collections::HashMap as Map;
use std::fmt::Result as FmtResult;
use std::io::Result as IoResult;

// ===== 自引用 =====
use std::io::{self, Write};  // self = std::io 本身
// 现在可以用 io::stdin() 和 io::Write::write()

// ===== 通配符导入 =====
use std::collections::*;  // 导入所有 pub 项（谨慎使用）

// ===== 重新导出 =====
pub use crate::front_of_house::hosting;
// 让外部可以用 my_crate::hosting::add_to_waitlist()
// 而不是 my_crate::front_of_house::hosting::add_to_waitlist()

// ===== 外部 crate =====
// Cargo.toml 中加入了 rand = "0.8"
use rand::Rng;  // 外部 crate 直接通过名字使用
```

**路径选择——绝对 vs 相对：**

```rust
// 一般建议：使用绝对路径（从 crate 根开始）
// 因为相对路径在重构（移动模块）时容易断

mod module_a {
    pub fn foo() {}
    
    pub mod module_b {
        pub fn bar() {
            // 推荐：绝对路径
            crate::module_a::foo();
            
            // 也可以：相对路径
            // super::foo();  // super = module_a
        }
    }
}
```

**单元测试——深入：**

```rust
// ===== src/lib.rs =====
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

// 私有函数也可以测试！
fn internal_helper(x: i32) -> i32 {
    x * 2
}

// 测试模块约定：和被测代码放在同一文件中
// #[cfg(test)] 确保测试代码只在 cargo test 时编译
#[cfg(test)]
mod tests {
    use super::*;  // 引入父模块的所有代码
    
    #[test]
    fn test_add() {
        assert_eq!(add(2, 2), 4);
        assert_ne!(add(2, 2), 5);
    }
    
    #[test]
    fn test_add_negative() {
        assert_eq!(add(-1, 1), 0);
    }
    
    #[test]
    fn test_internal() {
        // 可以测试私有函数！
        assert_eq!(internal_helper(5), 10);
    }
    
    #[test]
    #[should_panic(expected = "越界")]  // 预期会 panic
    fn test_panic() {
        panic!("越界");  // 这个测试应该通过（因为确实 panic 了）
    }
    
    #[test]
    fn test_with_result() -> Result<(), String> {
        // 测试也可以返回 Result
        if add(2, 2) == 4 {
            Ok(())
        } else {
            Err(String::from("加法错误"))
        }
    }
    
    #[test]
    #[ignore]  // 忽略这个测试（默认不运行）
    fn expensive_test() {
        // 很慢的测试
    }
}
```

**build.rs——构建脚本：**

```rust
// ===== build.rs（放在项目根目录）=====
// 在编译 main.rs/lib.rs 之前运行

fn main() {
    // 1. 生成代码
    println!("cargo:rerun-if-changed=src/protos/");
    prost_build::compile_protos(
        &["src/protos/messages.proto"],
        &["src/protos/"]
    ).unwrap();
    
    // 2. 编译 C 代码
    cc::Build::new()
        .file("src/native/helper.c")
        .compile("helper");
    
    // 3. 设置环境变量（可以在 Rust 中通过 env!() 获取）
    println!("cargo:rustc-cfg=BUILD_TIME=\"{}\"", 
             std::time::SystemTime::now()
                 .duration_since(std::time::UNIX_EPOCH)
                 .unwrap()
                 .as_secs());
    
    // 4. 链接系统库
    println!("cargo:rustc-link-lib=ssl");
    println!("cargo:rustc-link-search=/usr/local/lib");
}
```

**feature flags——条件特性：**


|------|--------|
| `mod` 声明 | 自动查找 `name.rs` 或 `name/mod.rs` |

| `build.rs` | 编译前运行；代码生成、链接 C 库 |
| feature flags | 可选依赖 + 条件编译、`default = [...]` |
| workspace | 共享 Cargo.lock、统一依赖版本 |
