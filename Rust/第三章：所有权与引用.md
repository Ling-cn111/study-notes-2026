## 第三章：所有权与引用

### ① 核心概念

**一句话总结：**
> 所有权是 Rust 最独特的概念——每个值有且只有一个"主人"（owner），当主人离开作用域时值被自动释放；借用的引用必须遵守"要么多个不可变，要么唯一可变"的规则，否则编译器拒绝通过。

**生活类比：**
- **所有权** = 你买了一本书，你是唯一的主人。当你离开房间（函数结束），书就被自动带走（drop）
- **借用（引用 &T）** = 你把书借给朋友看（只有阅读权），朋友看完还给你，书仍然是你的
- **可变借用（&mut T）** = 你让朋友在书上写笔记（读写权），但朋友写的时候你不能同时看（不能同时读写），而且其他人也不能看
- **Move** = 你把书卖给朋友——书不再属于你，你不能再使用它。朋友成为新的主人
- **Copy 类型** = 你告诉朋友一个数字（比如 42），你仍然记得它——因为数字是可以"复印"的

**用 C 的视角理解：**
- C 的 `free` 是手动的：`int* p = malloc(sizeof(int)); ... free(p);`
- Rust 的所有权是**自动的**：值离开作用域自动调用 `drop`（类似 C++ 的 RAII，但编译器还会检查你是否还在用它）
- C 的指针可以随意拷贝，Rust 的引用有严格的借用规则
- C 中 `int a = 5; int b = a;` 两者都是"主人"，Rust 中同样的行为叫 `Copy`，但 `String` 不是 Copy 的

**Rust 内存管理的"三定"原则：**

| 规则 | 说明 |
|------|------|
| **定主** | 每个值在任意时刻有且只有一个所有者 |
| **定命** | 引用（借用）不能比被引用的值活得更久 |
| **定访** | 要么同时有**多个不可变引用**，要么**唯一一个可变引用**，不能并存 |

### ② 为什么需要它？

**解决什么痛点？（C 编程中最头疼的四个问题）**

1. **内存泄漏**：C 中忘记 `free`，内存泄漏累积；Java 中 GC 兜底但不确定何时释放，且影响性能
2. **悬垂指针**：C 中函数返回局部变量的地址，调用方拿到野指针——Rust 编译器直接不允许
3. **数据竞争**：多线程中一个线程写、另一个线程同时读，无保护——Rust 的借用规则从根源上防止
4. **多次释放 / Use-after-free**：C 中对同一块内存 `free` 两次，或在 `free` 后继续使用——UB，Rust 编译器直接拒绝

**跟 C 的对比：**

| 场景 | C 的做法 | C 潜在问题 | Rust 的做法 |
|------|----------|-----------|-------------|
| 变量离开函数 | 栈变量自动回收 | 取地址返回变成悬垂指针 | 编译器禁止返回引用（除非借用来自参数） |
| 赋值 `a = b` | 复制值 | 指针复制后两个指针指向同一块内存 | Move（默认）或 Copy |
| 多线程访问 | 手动加锁 | 容易忘了加或死锁 | 借用检查器编译时阻止数据竞争 |
| 动态内存释放 | `free(p)` | 忘了 free / 重复 free | 自动 drop，编译时检查 |

### ③ 精简代码示例

**所有权规则——Move 语义：**

```rust
fn main() {
    let s1 = String::from("hello");  // s1 "拥有"这个 String
    let s2 = s1;                     // 所有权转移（move）给 s2
    // println!("{}", s1);           // 编译错误！s1 已失效
    // error[E0382]: borrow of moved value: `s1`
    
    // 如果需要"拷贝"，必须显式调用 clone
    let s3 = s2.clone();             // 深拷贝（堆上数据也复制一份）
    println!("s2 = {}, s3 = {}", s2, s3);  // 两者都可用
    
    // 什么是 Copy 类型？——存储在栈上的简单类型
    let x = 5;        // i32 实现了 Copy trait
    let y = x;        // x 仍然有效！因为 i32 是 Copy 的
    println!("x = {}, y = {}", x, y);  // 没问题
    
    // 哪些类型是 Copy 的？
    // 所有整数类型：i32, u32, ...
    // 所有浮点类型：f64, f32
    // 布尔类型：bool
    // 字符类型：char
    // 元组：仅当所有元素都是 Copy 时（如 (i32, i32)）
    // 数组：同理
}
```

**深入理解 Move——函数传参和返回值：**

```rust
fn main() {
    let s = String::from("hello");
    
    // 传参 = move
    takes_ownership(s);
    // s 不再有效 ↓
    // println!("{}", s);  // 编译错误！
    
    // 返回值 = move（所有权从函数内转移回来）
    let s2 = gives_ownership();
    
    // 传参 + 返参（需要"借用"来避免）
    let s3 = String::from("world");
    let s3 = take_and_give_back(s3);
    println!("拿回来了: {}", s3);
}

fn takes_ownership(some_string: String) {
    println!("{}", some_string);
}  // 这里 String 被 drop（释放）

fn gives_ownership() -> String {
    String::from("hello")
}

fn take_and_give_back(a_string: String) -> String {
    a_string  // 所有权被返还
}
```

**借用与引用——不用转移所有权的做法：**

```rust
fn main() {
    let s = String::from("hello");
    
    // & 表示引用——借出，但不转移所有权
    let len = calculate_length(&s);
    // s 仍然有效！
    println!("'{}' 的长度是 {}", s, len);
}

// s 是 &String 类型——指向 String 的引用
fn calculate_length(s: &String) -> usize {
    s.len()  // 注意：s.len() 不需要解引用
}  // s 离开作用域，但因为是引用，不释放 String
```

**可变引用——一次只能有一个：**

```rust
fn main() {
    let mut s = String::from("hello");
    
    change(&mut s);
    println!("{}", s);  // "hello, world"
}

// &mut String 表示"可变引用"
fn change(s: &mut String) {
    s.push_str(", world");  // 通过可变引用修改
}
```

**借用规则的演示——看看编译器如何报错：**

```rust
fn main() {
    let mut s = String::from("hello");
    
    // 规则 1：多个不可变引用可以并存
    let r1 = &s;
    let r2 = &s;
    println!("{} {}", r1, r2);
    // 这里 r1 和 r2 不再使用（NLL: 非词法生命周期）
    
    // 规则 2：可变引用和不可变引用不能共存
    let r3 = &mut s;  // 注意：这行在 println 之后，所以 r1/r2 已不再使用
    println!("{}", r3);
    
    // --- 下面这个是编译错误的经典案例 ---
    // let r1 = &s;
    // let r2 = &s;
    // let r3 = &mut s;  // 错误！已经有了不可变引用
    // println!("{} {} {}", r1, r2, r3);
}
```

**NLL（Non-Lexical Lifetimes）——Rust 2018 引入的重要改进：**

```rust
// 在 Rust 2015 中，下面这段代码会报错：
fn main() {
    let mut s = String::from("hello");
    
    let r1 = &s;
    let r2 = &s;
    println!("{} {}", r1, r2);  // r1 和 r2 的使用到此为止
    
    // 在 NLL 之前：这里会报错，因为 r1 和 r2 的借用要到 } 才结束
    // 在 NLL 之后：编译器知道 r1/r2 不再使用，所以这里可以安全地创建可变引用
    let r3 = &mut s;
    println!("{}", r3);
}
```

**切片——没有所有权的"视图"：**

```rust
fn main() {
    let s = String::from("hello world");
    
    // 切片 [start..end]——左闭右开
    let hello = &s[0..5];   // "hello"
    let world = &s[6..11];  // "world"
    
    // 简写
    let hello = &s[..5];    // 从 0 开始可以省略 0
    let world = &s[6..];    // 到末尾可以省略结束位置
    let whole = &s[..];     // 整个字符串
    
    println!("{} {}", hello, world);
    
    // String 类型不可变时，也可以对数组切片
    let arr = [1, 2, 3, 4, 5];
    let slice = &arr[1..3];  // 类型是 &[i32]，内容是 [2, 3]
}

// 编写类似 C 语言的 "first_word" 函数
fn first_word(s: &str) -> &str {
    // &str 比 &String 更通用（可以接受 &String 和 &str）
    let bytes = s.as_bytes();
    
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    
    &s[..]  // 没有空格，返回整个字符串
}

// 测试 first_word
fn test_first_word() {
    let s = String::from("hello world");
    let word = first_word(&s);
    println!("第一个单词: {}", word);  // "hello"
    
    // 注意：因为所有权规则，下面这段代码展示了切片和借用如何防止数据竞争
    // s.clear();  // 如果这里 clear 了，word 就变成悬垂切片
    // error! 但 Rust 会阻止，因为 word 还在借用 s
}
```

**String 和 &str 的关系——理解所有权的关键：**

```
String       → 拥有所有权的字符串（堆分配，可修改）
&str         → 对字符串的引用（字符串切片，不可变）


String 的内部结构：
Stack:       Heap:
┌─────────┐  ┌───┬───┬───┬───┬───┐
│ ptr     │──→│ h │ e │ l │ l │ o │
│ len: 5  │   └───┴───┴───┴───┴───┘
│ cap: 5  │
└─────────┘

&str 的内部结构：
┌─────────┐  ↑ 指向堆上数据的某一段
│ ptr     │──┘
│ len: 5  │
└─────────┘
```

**Copy 和 Drop trait——自定义所有权的行为：**

```rust
// 实现 Copy 的类型：赋值时自动复制（栈上数据）
#[derive(Copy, Clone)]
struct MyInt(i32);  // 这个结构体现在是 Copy 的

// 实现 Drop 的类型：离开作用域时执行清理逻辑
struct Custom {
    data: String,
}

impl Drop for Custom {
    fn drop(&mut self) {
        println!("Custom 被释放了: {}", self.data);
        // 这里可以放资源清理代码（关闭文件、释放锁等）
    }
}

fn main() {
    let a = Custom { data: "hello".to_string() };
    println!("a 还在作用域");
    // a 离开作用域时，自动调用 drop
    // 输出：
    // a 还在作用域
    // a 被释放了: hello
}
```

**复合类型的 Move vs Copy——什么情况会 Move？**

```rust
fn main() {
    // 常见类型默认是 Move 还是 Copy？
    
    let x = 5;               // i32：Copy ✓
    let y = x;               // x 仍有效
    println!("{} {}", x, y);
    
    let s = "hello".to_string();  // String：Move ✗
    let t = s;                     // s 被移动
    // println!("{}", s);          // 错误！
    
    let arr = [1, 2, 3];    // [i32; 3]：Copy ✓
    let brr = arr;          // arr 仍有效
    
    let person = ("Alice".to_string(), 30);  // (String, i32)：Move ✗
    let moved = person;                       // 元组中只要有非 Copy 元素，整体就是 Move
    // println!("{:?}", person);             // 错误！
}
```

**关键点说明：**

| 概念 | 说明 |
|------|------|
| Move | 所有权转移，原变量失效。发生在赋值、函数传参、函数返回时 |
| Copy | 自动复制栈上数据，原变量仍有效。整数、浮点、bool、char 等简单类型 |
| Clone | `.clone()` 方法显式深拷贝，堆数据也复制一份 |
| 引用 `&T` | 借出只读访问权，不转移所有权 |
| 可变引用 `&mut T` | 借出读写访问权，同一时刻只能有一个 |
| 悬垂引用 | 引用指向已释放的内存，Rust 编译器阻止 |
| NLL | 非词法生命周期：引用不再使用后，借用在"最后一次使用"处结束 |
| Slice | 没有所有权的连续数据视图，类型为 `&[T]` 或 `&str` |
