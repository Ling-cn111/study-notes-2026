## 第一章：简介与开发套件

### ① 核心概念

**一句话总结：**
> Rust 是一门系统级编程语言，主打"内存安全无需GC"和"零成本抽象"，由 Mozilla 于 2015 年发布，连续多年被评为"最受开发者喜爱的语言"。

**生活类比：**
- **C/C++** = 手动挡汽车——性能好但容易熄火（内存泄漏、空指针、段错误）
- **Java/Go** = 自动挡汽车——安全但多了变速箱损耗（GC 暂停、吞吐量损失）
- **Rust** = 有智能辅助的手动挡——既有手动挡的性能，又有自动挡的安全（编译器替你检查所有操作，相当于 AI 副驾时刻盯着你有没有违规）

**用 C 的视角理解：**
Rust 的 `cargo` 相当于 C 的 `make` + `pkg-config` + 文档生成器（doxygen）+ 单元测试框架 + 包管理器（apt/vcpkg）合为一体。一个 `cargo build` 搞定一切。

**Rust 语言的三个核心理念：**

1. **内存安全**：不使用 GC 的前提下，编译器通过所有权系统保证内存安全
2. **零成本抽象**：高级特性（迭代器、闭包、泛型）编译后与手写底层性能一致——你不需要在"可读性"和"性能"之间做取舍
3. **实用主义**：包管理器、构建工具、测试框架、格式化工具、文档生成器全部官方提供，开箱即用

### ② 为什么需要它？

**解决什么痛点？**

1. **内存安全问题（C 的头号杀手）**：
   - C 中 `free` 后继续用（use-after-free）、越界访问（buffer overflow）、空指针解引用——这些 Bug 占安全漏洞的 70%
   - 微软安全团队报告：过去 10 年微软 70% 的 CVE 是内存安全漏洞
   - Rust 在编译时就能杜绝这些——**不需要你写任何 extra 代码**

2. **数据竞争**：
   - 多线程中不加锁访问共享数据，C 中完全靠程序员自觉
   - Rust 的借用检查器在**编译时**防止数据竞争——同一时刻要么一个可变引用，要么多个不可变引用

3. **依赖管理混乱**：
   - C 项目没有统一包管理器，`make` + 手动下载库令人头疼
   - C++ 的 CMake + Conan/vcpkg 配置复杂，学习曲线陡峭
   - Rust 的 Cargo + crates.io 像 npm/pip 一样简单：一行声明，`cargo build` 自动下载

4. **大型项目重构困难**：
   - C 中改一个头文件可能导致全项目重新编译，且牵一发动全身
   - Rust 的模块系统和编译器错误信息让你**放心重构**——改完后编译器告诉你哪里需要同步修改

**Rust 的方案：**

| 问题 | C/C++ 的做法 | Rust 的做法 |
|------|-------------|-------------|
| 内存管理 | 手动 `malloc`/`free` | 所有权系统自动管理 |
| 空指针 | NULL，随时可能解引用 | `Option<T>`，必须显式处理 |
| 错误处理 | 忽略返回值 / errno | `Result<T, E>`，必须处理 |
| 构建工具 | Make/CMake + 各种脚本 | Cargo 一站式 |
| 包管理 | 无官方方案 | crates.io + Cargo |
| 并发 | 全靠程序员，容易出数据竞争 | 编译器保证无数据竞争 |
| 泛型 | 宏 / void* / 模板（C++） | 泛型 + trait bound，类型安全 |

**核心优势速览：**

| 优势 | 说明 | 对比 C |
|------|------|--------|
| 内存安全 | 编译时保证无空指针、无野指针、无内存泄漏 | C 全靠手动管理 |
| 无 GC | 零运行时开销，性能与 C 相当 | Java/Go 有 GC 停顿 |
| 并发安全 | 编译器防止数据竞争 | C 需手动加锁，容易出错 |
| 零成本抽象 | 高级抽象编译后和手写底层一样高效 | C++ 部分特性有运行时开销 |
| 包管理 | Cargo 一站式构建/测试/发布 | C 无官方包管理器 |
| 错误信息 | 编译器给出的信息极其详细，有提示建议 | GCC 的错误信息相对晦涩 |
| 互操作性 | 通过 FFI 无缝调用 C 代码 | 可以直接与 C 库链接 |

**现在谁在用 Rust？**
- **Firefox**（Mozilla）：CSS 引擎 Servo，大幅提升浏览器性能
- **AWS**：用 Rust 重写了基础设施（如 Firecracker microVM）
- **Dropbox**：文件同步引擎核心用 Rust 重写
- **Cloudflare**：网络基础设施大量使用 Rust
- **Microsoft**：Windows 内核组件用 Rust 重写
- **Linux 内核**：2022 年起官方支持 Rust 作为第二语言

### ③ 精简代码示例

**安装 Rust（推荐使用 rustup）：**

```bash
# 安装（macOS/Linux）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Windows 到 https://rustup.rs 下载安装程序

# 验证安装
rustc --version   # 编译器版本，例如 rustc 1.70.0
cargo --version   # 包管理器版本

# 列出已安装的工具链
rustup toolchain list

# 安装 nightly 版本（需要使用不稳定特性时）
rustup install nightly

# 切换默认工具链
rustup default stable
rustup default nightly
```

**第一个 Rust 程序：**

```rust
fn main() {
    println!("Hello, Rust!");
}
```

**编译运行：**
```bash
rustc hello.rs    # 直接编译，生成可执行文件
./hello           # 运行（Linux/macOS）
.\hello.exe       # 运行（Windows）
```

**用 Cargo 创建项目（推荐方式）：**

```bash
cargo new my_project     # 创建新项目（二进制）
cd my_project
cargo run                # 编译并运行
```

**Cargo 创建的项目结构：**

```
my_project/
├── Cargo.toml    # 项目配置和依赖声明
├── Cargo.lock    # 依赖版本锁定文件（自动生成，需提交到 VCS）
├── src/
│   └── main.rs   # 程序入口
└── .gitignore    # git 忽略规则（自动生成）
```

**Cargo.toml 详解：**

```toml
[package]
name = "my_project"       # 包名（也是 crates.io 上的名字）
version = "0.1.0"         # 语义化版本
edition = "2021"          # Rust 版本：2015 / 2018 / 2021 / 2024
authors = ["Your Name"]   # 可选
description = "..."       # 可选

[dependencies]
# 从 crates.io 拉取
serde = "1.0"                      # ^1.0，兼容 1.x.x
serde_json = { version = "1.0", features = ["preserve_order"] }

# 指定 Git 仓库
my_lib = { git = "https://github.com/user/repo.git", branch = "main" }

# 指定本地路径（开发时常用）
my_local = { path = "../my_local_crate" }

# 可选依赖（通过 feature 启用）
tokio = { version = "1", optional = true }

[profile.release]
opt-level = 3        # 优化级别 0-3
lto = true           # 链接时优化
codegen-units = 1    # 单代码生成单元（更优优化）
```

**Cargo 的常用命令：**

```bash
cargo new <name>            # 创建新项目
cargo new <name> --lib      # 创建库项目（生成 lib.rs，不是 main.rs）
cargo build                 # 编译（debug 模式）
cargo build --release       # 编译（release 模式，带优化）
cargo run                   # 编译 + 运行
cargo check                 # 快速检查语法错误（不生成可执行文件，比 build 快很多！）
cargo test                  # 运行测试
cargo clippy                # 运行 linter（代码质量检查）
cargo fmt                   # 自动格式化代码
cargo doc --open            # 生成文档并在浏览器打开
cargo update                # 更新 Cargo.lock 中的依赖版本
cargo clean                 # 清理编译产物（target/ 目录）

# 查看依赖图
cargo tree

# 添加依赖（自动修改 Cargo.toml）
cargo add serde
cargo add tokio --features full
```

**Rust 编译模型：**

Rust 的编译流程比 C 复杂，理解它对调试编译问题有帮助：

```
源代码 (.rs)
    │
    ▼
词法分析 → 语法分析 → AST（抽象语法树）
    │
    ▼
HIR（高级中间表示）← 宏展开在此阶段发生
    │
    ▼
类型检查 + 借用检查 ← 所有权规则在此检查
    │
    ▼
THIR（类型化高级中间表示）
    │
    ▼
MIR（中级中间表示）← 生命周期在此检查，也是 borrow checker 的主要工作对象
    │
    ▼
代码生成（LLVM / Cranelift）
    │
    ▼
优化 → 汇编 → 链接
    │
    ▼
可执行文件 / 库
```

**关键术语解释：**
| 术语 | 解释 | 类比 C |
|------|------|--------|
| rustc | Rust 编译器 | gcc / clang |
| cargo | 包管理器和构建系统 | make + apt |
| rustup | Rust 工具链管理器 | nvm（Node.js） |
| crate | Rust 的编译单元（一个包） | .a / .so 库 |
| target | 编译目标目录 | build/ 目录 |
| edition | Rust 版本体系 | C 标准版本 C11/C17 |

**Debug vs Release 构建：**

```bash
# Debug（默认）
cargo build
# 特点：编译快、无优化、有调试符号、运行时检查（整数溢出 check）

# Release
cargo build --release  
# 特点：编译慢（优化耗时长）、运行快、无调试符号
# 去掉了一些安全检查（如整数溢出按环绕处理）
```

**Cargo.toml 中的 profile 配置：**

```toml
[profile.dev]
opt-level = 0       # debug 不优化
debug = true        # 保留调试符号

[profile.release]
opt-level = 3       # 最大优化
debug = false       # 去掉调试符号
lto = true          # 链接时优化（减小体积、提升性能）
strip = true        # 剥离符号表（减小体积）
```

**rustfmt 和 clippy——代码质量工具：**

```rust
// 格式化前
fn main(){
let x=42;
println! ("x is {}",x);
}

// 运行 cargo fmt 后
fn main() {
    let x = 42;
    println!("x is {}", x);
}
```

```bash
# clippy 不仅检查错误，还会给出改进建议
cargo clippy

# 示例输出：
# warning: you should consider adding a `Default` implementation for `MyStruct`
# --> src/main.rs:10:5
```

**rustup 进阶——管理多个工具链：**

```bash
# 查看所有可用的 targets
rustup target list

# 安装交叉编译目标（例如为 ARM 编译）
rustup target add aarch64-unknown-linux-gnu

# 交叉编译
cargo build --target aarch64-unknown-linux-gnu

# 在特定工具链下运行
cargo +nightly build
cargo +1.60.0 run
```

**关键点说明：**
- `rustc` 直接编译单个文件，`cargo` 管理整个项目——日常 99% 用 `cargo`
- `cargo check` 比 `cargo build` 快得多，开发时常用 `cargo check` 检查语法
- Rust 的 `edition` 不是"大版本"，而是"新特性开关"——不同 edition 代码可以互相调用
- `Cargo.lock` 保证可重复构建（类似 npm 的 `package-lock.json`），**必须提交到 git**
- `cargo clippy` 和 `cargo fmt` 是**官方推荐**的代码质量工具，建议 CI 中强制执行
