## 补充章节：栈、堆与内存管理

### ① 核心概念

**一句话总结：**
> JVM内存分为三块主要区域：**栈（Stack）** 存局部变量和方法调用，**堆（Heap）** 存所有对象，**方法区（Method Area）** 存类信息和静态变量。

**生活类比：**
- **栈** = 厨房的**操作台**（临时放菜、工具，用完即清理，LIFO后进先出）
- **堆** = 厨房的**大仓库**（存储所有食材/厨具，需要时取用，不用时由管理员回收）
- **方法区** = **菜谱书架**（存放所有菜谱和烹饪规则，所有人都能查阅）

**用C的视角理解：**
栈 ≈ C的局部变量+函数调用栈，堆 ≈ malloc分配的内存，方法区 ≈ 全局区/代码区，但Java多了自动垃圾回收（GC）。

### ④ 栈（Stack）详解

**存放内容：**
- 基本类型变量的值（`int a = 10` 直接存10）
- 引用类型变量的地址（`String s` 存的是指向堆中对象的地址）
- 方法调用信息（参数、返回地址、操作数栈）

**特点：**
```java
public class StackDemo {
    public static void main(String[] args) {   // ① main栈帧入栈
        int a = 10;                            // ② 局部变量a在栈中
        String s = "Hello";                    // ③ 变量s存地址，指向常量池
        method1(a);                            // ④ method1栈帧入栈
    }                                          // ⑤ main栈帧出栈（程序结束）
    
    public static void method1(int x) {        // ⑥ method1栈帧入栈
        int y = x + 5;                         // ⑦ y在method1栈中
    }                                          // ⑧ method1栈帧出栈（方法返回）
}
```

**栈的规则（LIFO - 后进先出）：**
```
调用顺序：main() → method1() → method2()
栈结构（从上到下是入栈顺序）：
┌─────────────┐  ← 栈顶
│ method2()   │  最后调用，最先返回
├─────────────┤
│ method1()   │  中间调用，中间返回
├─────────────┤
│ main()      │  最先调用，最后返回
└─────────────┘
```

**栈溢出（StackOverflowError）：**
```java
// 递归调用没有出口，栈不断压帧，直到内存耗尽
public void infiniteRecursion() {
    infiniteRecursion();  // 不断调用自己，栈帧无限增加
}
// 报错：Exception in thread "main" java.lang.StackOverflowError
```

### ⑤ 堆（Heap）详解

**存放内容：**
- 所有通过 `new` 创建的对象
- 数组
- 字符串常量池中的字符串对象（部分）

**特点：**
```java
public class HeapDemo {
    public static void main(String[] args) {
        // ① p1在栈中存地址，对象在堆中
        Person p1 = new Person("张三");
        
        // ② p2和p1指向同一个堆对象（赋值是地址拷贝）
        Person p2 = p1;
        p2.name = "李四";  // 修改p2，p1也变了
        
        System.out.println(p1.name);  // 李四
        
        // ③ 数组也是对象，在堆中
        int[] arr = new int[10];  // arr存地址，数组在堆中
    }
}

class Person {
    String name;  // name本身是引用，指向堆中的字符串对象
    Person(String name) {
        this.name = name;
    }
}
```

**内存示意图：**
```
栈内存                    堆内存
┌─────────────┐           ┌─────────────────────────┐
│ p1 = 0x100  │───────────│ 0x100: Person对象       │
├─────────────┤           │        name = 0x200     │──┐
│ p2 = 0x100  │───────────│        (指向字符串)      │  │
├─────────────┤           ├─────────────────────────┤  │
│ arr = 0x300 │───────────│ 0x300: int[10]          │  │
└─────────────┘           └─────────────────────────┘  │
                                                          │
                     ┌────────────────────────────────────┘
                     ↓
         常量池/堆   ┌─────────────────────────┐
                     │ 0x200: "张三" (字符串)   │
                     └─────────────────────────┘
```

### ⑥ 方法区（Method Area）详解

**存放内容：**
- 类元信息（类名、方法名、字段名）
- 静态变量（`static` 修饰的变量）
- 常量池（字符串常量、数字常量）
- JIT编译后的代码

```java
public class MethodAreaDemo {
    // 静态变量存放在方法区
    private static int count = 0;
    private static final String COMPANY = "网络科技公司";
    
    // 类信息存放在方法区
    public void method() {
        // "Hello" 字符串常量放在常量池（方法区）
        String s = "Hello";
    }
}
```

### ⑦ 引用传递 vs 值传递（重点）

**一句话总结：**
> Java只有值传递——基本类型传递值副本，引用类型传递地址的副本（但地址指向同一个对象）。

```java
public class PassDemo {
    public static void main(String[] args) {
        // 场景1：基本类型（值传递）
        int a = 10;
        changeInt(a);
        System.out.println(a);  // 10，没变！
        
        // 场景2：引用类型（地址传递）
        Person p = new Person("张三");
        changePerson(p);
        System.out.println(p.name);  // 李四，变了！
        
        // 场景3：引用类型重新赋值（不影响原引用）
        Person p2 = new Person("王五");
        changePersonRef(p2);
        System.out.println(p2.name);  // 王五，没变！
    }
    
    public static void changeInt(int x) {
        x = 20;  // 修改的是副本，不影响原来的a
    }
    
    public static void changePerson(Person p) {
        p.name = "李四";  // 修改的是同一个堆对象，影响原对象
    }
    
    public static void changePersonRef(Person p) {
        p = new Person("赵六");  // p重新指向新对象，不影响原引用
    }
}
```

**内存解释：**
```
主方法中：          changePersonRef方法中：
┌──────────┐        ┌──────────┐
│ p2 = 0x100│───────→│ p = 0x100│  ← 开始时指向同一个对象
└──────────┘        └──────────┘
                         ↓
                    p = new Person("赵六")
                         ↓
                    ┌──────────┐
                    │ p = 0x200│  ← 重新指向新对象
                    └──────────┘

原来的 p2 仍然指向 0x100，不受影响！
```

### ⑧ 垃圾回收（GC）简介

**一句话总结：**
> Java自动管理堆内存——当对象不再被任何引用指向时，GC会在适当时候回收它的内存。

```java
public class GCDemo {
    public static void main(String[] args) {
        // 创建对象
        Person p = new Person("张三");
        
        // 引用置为null，对象不再被引用，成为GC候选
        p = null;
        
        // 建议JVM执行GC（但不保证立刻执行）
        System.gc();
        
        // 注意：弱引用、软引用等可以影响GC行为
    }
}

// 可以在对象被回收前执行清理
class Person {
    @Override
    protected void finalize() throws Throwable {
        System.out.println("Person对象被回收了");
        super.finalize();
    }
}
```

**什么对象会被回收？**
```
┌─────────────┐
│ 对象被回收   │
│  (GC Roots)  │
├─────────────┤
│  ✓ 方法区静态变量引用的对象  → 不会被回收
│  ✓ 栈中局部变量引用的对象    → 不会被回收
│  ✓ 没有任何引用指向的对象    → 被回收 ✅
└─────────────┘
```

### ⑨ 常见内存问题与优化

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| `StackOverflowError` | 递归太深/方法调用层数过多 | 改用迭代，或增加栈大小 `-Xss` |
| `OutOfMemoryError: Java heap space` | 创建了太多对象，堆内存耗尽 | 使用内存分析工具，优化代码 |
| 内存泄漏 | 无用对象被意外引用，无法回收 | 及时释放引用（如集合中的对象） |

```java
// 内存泄漏示例：长生命周期的对象持有短生命周期对象的引用
class LeakExample {
    private static List<byte[]> cache = new ArrayList<>();
    
    public void addData() {
        // 不断添加，从不清理 → 内存溢出
        cache.add(new byte[1024 * 1024]);  // 每次1MB
    }
}

// 正确做法：使用软引用或弱引用，或定期清理
class GoodExample {
    private static List<SoftReference<byte[]>> cache = new ArrayList<>();
    
    public void addData() {
        cache.add(new SoftReference<>(new byte[1024 * 1024]));
        // 内存不足时自动回收软引用
    }
}
```
