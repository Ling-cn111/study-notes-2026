# **第六章 技术栈对比表**

前面五章我们把产品形态、编程语言、框架、数据库分别讲了一遍。信息量很大，但你可能已经有点记不清了。这一章的作用是把关键信息汇总成表格，方便你快速对比、筛选、做决定。表格之后我会附上解读，帮你理解每个选项背后的取舍逻辑。

表格里的“新手推荐度”和“vibe coding 友好度”是综合评分，满分五星。评分依据包括：学习曲线、生态大小、文档质量、社区活跃度、AI 生成代码的准确率、就业机会。评分带有主观判断，但方向是稳的：主流、成熟、生态大的技术，评分更高。

---

## **6.1 按产品形态对比**

| 产品形态 | 特色 | 适用场景 | 学习成本 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|
| Web 应用 | 跨平台、更新快、无需安装 | 官网、SaaS、后台、电商、社区 | 低 | ★★★★★ | ★★★★★ |
| 移动应用 | 手机原生体验、可调硬件 | 社交、工具、电商、健康 | 中 | ★★★☆☆ | ★★★★☆ |
| 桌面应用 | 性能强、可离线、本地文件 | 工具、编辑器、企业内部软件 | 中 | ★★★☆☆ | ★★★★☆ |
| 小程序 | 免安装、平台流量、开发快 | 电商、预约、点餐、轻工具 | 中低 | ★★★★☆ | ★★★★☆ |
| API 服务 | 无界面、供程序调用 | 后端、微服务、AI 服务 | 中 | ★★★★☆ | ★★★★★ |
| AI 应用 | 大模型、RAG、Agent | 问答、知识库、内容生成 | 中 | ★★★★☆ | ★★★★★ |
| 浏览器扩展 | 轻量、增强网页、开发简单 | 翻译、笔记、效率工具 | 低 | ★★★★☆ | ★★★★☆ |
| 自动化脚本 | 小快灵、解决重复劳动 | 爬虫、文件处理、定时任务 | 低 | ★★★★★ | ★★★★★ |

**解读**：Web 应用和自动化脚本是新手最友好的两个方向。Web 应用生态最大，AI 支持最好，部署成本低；自动化脚本门槛最低，几行代码就能出成果。移动应用和桌面应用学习成本中等，涉及打包、签名、审核、跨平台适配，新手容易卡在非代码环节。小程序开发本身不难，但受平台规则限制，审核和资质要提前了解。API 服务和 AI 应用是当前需求增长最快的方向，适合有一定基础后深入。

如果你完全不知道选什么，先从 Web 应用或自动化脚本入手。做出一个能跑的东西，比纠结选什么更重要。

## **6.2 按编程语言对比**

| 语言 | 核心特色 | 典型用途 | 学习曲线 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|
| JavaScript / TypeScript | 浏览器唯一原生、全栈通吃 | Web、Node、移动、桌面、扩展 | 低到中 | ★★★★★ | ★★★★★ |
| Python | 简单、库多、AI 首选 | AI、数据、脚本、后端、自动化 | 低 | ★★★★★ | ★★★★★ |
| Java | 企业级、稳定、生态成熟 | 企业后端、金融、Android | 中高 | ★★★☆☆ | ★★★★☆ |
| Go | 简单、并发强、部署方便 | 后端、云原生、CLI、微服务 | 中 | ★★★★☆ | ★★★★☆ |
| Rust | 内存安全、高性能、无 GC | 系统、嵌入式、WASM、Tauri | 高 | ★★☆☆☆ | ★★★☆☆ |
| C# | 微软生态、现代语法、Unity | Windows、游戏、企业后端 | 中 | ★★★★☆ | ★★★★☆ |
| Kotlin | Android 官方、简洁、空安全 | Android、后端、跨平台 | 中 | ★★★★☆ | ★★★★☆ |
| Swift | Apple 官方、现代、安全 | iOS、macOS、watchOS | 中 | ★★★★☆ | ★★★★☆ |
| PHP | 建站快、部署简单、生态成熟 | 网站、CMS、电商、API | 低 | ★★★★☆ | ★★★★☆ |
| Ruby | 优雅、开发快、Rails 强 | Web、MVP、原型、内部工具 | 低到中 | ★★★☆☆ | ★★★★☆ |

**解读**：TypeScript 和 Python 是新手最值得投入的两门语言。TypeScript 覆盖前端、后端、移动、桌面、扩展，生态最大，AI 最熟悉；Python 覆盖 AI、数据、脚本、后端，语法最简单，库最丰富。两门都学，基本能覆盖绝大多数项目。

Java 和 C# 适合目标明确的人：想进大公司做企业后端，学 Java；想做 Windows 桌面或 Unity 游戏，学 C#。Go 适合做高并发后端和云原生工具，学习曲线比 Java 低，部署比 Python 方便。Rust 性能和安全最好，但学习曲线最陡，不建议新手直接学。Kotlin 和 Swift 分别绑定 Android 和 Apple 生态，目标明确再学。PHP 和 Ruby 适合快速建站和 MVP，但新项目比例在下降。

新手建议：先学 TypeScript 或 Python，做出项目后再扩展。不要同时学多门语言。

## **6.3 按前端框架对比**

| 框架 | 类型 | 特色 | 适用场景 | 学习成本 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|---|
| React | 前端库 | 生态最大、灵活、组件化 | 几乎所有 Web 前端 | 中 | ★★★★★ | ★★★★★ |
| Vue | 前端框架 | 渐进式、模板语法、中文多 | 中小型 Web、后台 | 低到中 | ★★★★★ | ★★★★★ |
| Svelte | 前端框架 | 编译时、代码少、性能好 | 小中型、追求简洁 | 低 | ★★★★☆ | ★★★★☆ |
| Angular | 前端框架 | 企业级、全功能、TypeScript | 大型企业应用 | 高 | ★★★☆☆ | ★★★☆☆ |
| Next.js | React 全栈 | SSR / SSG / API、全栈 | SaaS、官网、AI 前端 | 中 | ★★★★★ | ★★★★★ |
| Nuxt | Vue 全栈 | SSR / SSG / API、Vue 生态 | SEO 网站、Vue 全栈 | 中 | ★★★★☆ | ★★★★☆ |

**解读**：React + Next.js 是当前最稳的前端组合。React 生态最大，Next.js 补齐了 SSR、路由、API、部署，Vercel 一键上线，AI 支持极好。Vue + Nuxt 是国内最流行的组合，中文资料多，上手快，适合后台系统和中小型项目。Svelte 适合追求简洁和性能的人，但生态较小，遇到问题资料少。Angular 适合大型企业，学习曲线陡，新手慎入。

如果你不确定，选 React + Next.js。如果你在国内、喜欢简单、做后台，选 Vue + Nuxt。

## **6.4 按后端框架对比**

| 框架 | 语言 | 特色 | 适用场景 | 学习成本 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|---|
| Express | Node.js | 轻量、灵活、中间件多 | 小 API、原型、实时 | 低 | ★★★★☆ | ★★★★★ |
| NestJS | Node.js | 结构化、TypeScript、企业级 | 中大型 Node 后端 | 中 | ★★★★☆ | ★★★★☆ |
| Django | Python | 全包、Admin、ORM、认证 | 内容网站、后台、CMS | 中 | ★★★★☆ | ★★★★☆ |
| Flask | Python | 微框架、简单、灵活 | 小 API、原型、学习 | 低 | ★★★★☆ | ★★★★☆ |
| FastAPI | Python | 异步、类型提示、自动文档 | API、AI 服务、微服务 | 低到中 | ★★★★★ | ★★★★★ |
| Spring Boot | Java | 企业级、生态极大、稳定 | 大型企业、金融、电商 | 高 | ★★★☆☆ | ★★★★☆ |
| Gin | Go | 高性能、简洁、中间件 | 高并发 API、微服务 | 中 | ★★★★☆ | ★★★★☆ |
| Laravel | PHP | 优雅、功能全、生态大 | Web、CMS、电商、API | 低到中 | ★★★★☆ | ★★★★☆ |
| Rails | Ruby | 约定优于配置、开发快 | MVP、内容网站、内部工具 | 中 | ★★★☆☆ | ★★★★☆ |

**解读**：Python 阵营，FastAPI 是当前最推荐的选择，异步、类型提示、自动文档，AI 友好度满分。Django 适合需要 Admin 和全功能 Web 的项目。Node.js 阵营，Express 适合小型，NestJS 适合中大型。Java 的 Spring Boot 是企业后端标准，但学习曲线高。Go 的 Gin 适合高并发和云原生。PHP 的 Laravel 和 Ruby 的 Rails 适合快速建站和 MVP。

新手最稳的后端组合：FastAPI + Python（做 AI / API）或 NestJS + TypeScript（做中大型 Node 后端）。如果你做全栈，Next.js API Routes 也能覆盖简单后端。

## **6.5 按移动端框架对比**

| 框架 | 语言 | 特色 | 适用场景 | 学习成本 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|---|
| React Native | JS / TS | React 写移动、生态大 | 跨平台 App、前端转型 | 中 | ★★★★☆ | ★★★★☆ |

## **6.7 按数据库对比**

| 数据库 | 类型 | 特色 | 适用场景 | 学习成本 | 新手推荐度 | vibe coding 友好度 |
|---|---|---|---|---|---|---|
| PostgreSQL | 关系型 | 功能强、扩展好、支持向量 | 大多数项目、AI 检索 | 中 | ★★★★★ | ★★★★★ |
| MySQL | 关系型 | 常见、教程多、Web 常用 | Web、PHP、传统项目 | 低到中 | ★★★★☆ | ★★★★☆ |
| SQLite | 关系型 | 单文件、零配置、轻量 | 本地、原型、小工具 | 低 | ★★★★★ | ★★★★★ |
| MongoDB | 文档型 | 灵活、JSON 文档、易扩展 | 日志、灵活结构、原型 | 中 | ★★★★☆ | ★★★★☆ |
| Redis | 键值型 | 内存、极快、缓存队列 | 缓存、会话、排行榜 | 低到中 | ★★★★☆ | ★★★★☆ |
| pgvector | 向量扩展 | PostgreSQL 扩展、统一管理 | AI 检索、RAG | 中 | ★★★★☆ | ★★★★☆ |
| Chroma | 向量库 | 轻量、本地、易用 | AI 原型、学习 | 低 | ★★★★☆ | ★★★★☆ |
| Pinecone | 向量库 | 托管、省心、可扩展 | 大规模 AI 生产 | 中 | ★★★☆☆ | ★★★☆☆ |

**解读**：PostgreSQL 是默认推荐，能覆盖关系型、JSON、向量检索，一个数据库解决大部分需求。SQLite 适合本地和小工具。MySQL 适合 PHP 和传统 Web。MongoDB 适合灵活结构。Redis 做缓存。向量检索先用 pgvector 或 Chroma，规模大了再考虑 Pinecone 或 Milvus。

新手最稳：PostgreSQL + Redis（需要缓存时）+ pgvector（需要 AI 检索时）。小项目：SQLite。快速原型：Supabase（内置 PostgreSQL）。

## **6.9 综合推荐组合**

看完表格，你可能还是想要一个直接答案。下面给几套经过验证的组合，按场景分类。

**Web 全栈（最稳）**：TypeScript + Next.js + Tailwind CSS + PostgreSQL + Prisma + Vercel + Supabase Auth。适合官网、SaaS、后台、社区、电商。

**AI 应用（最稳）**：Python + FastAPI + LangChain / LlamaIndex + pgvector / Chroma + Next.js + Vercel。适合知识库、问答、内容生成、Agent。

**移动跨平台**：TypeScript + React Native + Supabase / Firebase。或 Dart + Flutter + Supabase / Firebase。适合 App、工具、社交。

**桌面工具**：TypeScript + Electron + SQLite。或 TypeScript + Tauri + Rust + SQLite。适合编辑器、工具、企业内部软件。

**小程序**：TypeScript + uni-app / Taro + 微信云开发 / Supabase。适合电商、预约、点餐。

**自动化脚本**：Python + requests / pandas / Playwright。适合爬虫、文件处理、定时任务。

**企业后端**：Java + Spring Boot + PostgreSQL + Redis + Docker。适合金融、电商、大型系统。

**高并发 API**：Go + Gin + PostgreSQL + Redis + Docker。适合微服务、云原生。

**快速 MVP**：TypeScript + Next.js + Supabase。适合创业验证、个人项目。

## **6.10 本章小结**

表格是工具，不是答案。同样的项目，不同的人、不同的预算、不同的时间，可能选不同的技术栈。表格帮你缩小范围，但最终决定要结合你的实际情况。

记住几个原则：主流优先，生态优先，AI 友好优先，部署成本优先，学习曲线匹配优先。不要为了“高级”选复杂技术，不要为了“灵活”选冷门框架，不要为了“快”忽略安全。
