# 第一章：基础命令与本地单分支工作流

## 📖 概述
本章目标：**在你自己电脑上完成首个Git仓库的完整生命周期**。我们将从安装开始，逐步学习 `init`、`add`、`commit`、`status`，并理解它们如何映射到"灶台→备餐盘→冰箱"的流程。全程在单分支（默认 `main`/`master`）上操作，不涉及协作。

---

## 1. 安装 Git

### 各平台安装方式

| 系统 | 方法 | 验证安装 |
|------|------|----------|
| **macOS** | `brew install git` (Homebrew) 或下载官方安装包 | 终端输 `git --version` |
| **Windows** | 下载 [Git for Windows](https://git-scm.com/download/win)，建议选"Git Bash Here" | 打开 Git Bash，输 `git --version` |
| **Linux (Ubuntu/Debian)** | `sudo apt install git` | 终端输 `git --version` |

**首次配置（全局身份，每次commit都会附带）**：
```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```

> **类比**：这相当于在菜谱上签名，告诉别人这道菜是谁做的。

## 2. git init —— 创建厨房

**作用**：在当前目录初始化一个空的Git仓库，生成 `.git` 隐藏文件夹（你的"冰箱+菜谱本"）。

**常用参数**：
- `git init [目录名]` —— 在指定目录创建仓库，不指定则用当前目录

**实操示例**：
```bash
# 创建一个学习项目文件夹
mkdir my-first-repo
cd my-first-repo

# 初始化仓库
git init

# 查看隐藏的.git目录（证明厨房已搭建）
ls -la
```

**终端输出**：
```
Initialized empty Git repository in /Users/你/Desktop/my-first-repo/.git/

# ls -la 会显示：
drwxr-xr-x   ... .git/
```

**常见误区**：
- ❌ 不要在已有 `.git` 的仓库里再执行 `git init`（会重新初始化，但不影响已有对象）
- ❌ 不要手动修改 `.git` 文件夹里的任何文件（除非你清楚在做什么）

---

## 3. git status —— 看看灶台上有什么

**作用**：查看当前工作区和暂存区的状态，告诉你哪些文件被修改、已暂存、未跟踪。

**一句话类比**：厨师巡视厨房，看看案板上有什么菜、备餐盘里放了什么、冰箱里存了什么。

**常用参数**：
- `git status -s` / `--short` —— 精简模式，输出更紧凑

**实操示例**（先创建一个文件）：
```bash
# 新建一个README文件
echo "# 我的第一个Git项目" > README.md

# 查看状态
git status
```

**终端输出**：
```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md

nothing added to commit but untracked files present (use "git add" to track)
```

**解读**：`README.md` 是"灶台上的新食材"（未跟踪），Git还没开始管它。

---

## 4. git add —— 把菜放进备餐盘

**作用**：将工作区的改动添加到暂存区（Staging Area），标记为"准备提交"。

**一句话类比**：把切好的菜从案板装到备餐盘里，等会儿一起下锅。

**常用参数**：

| 参数 | 作用 | 典型用法 |
|------|------|----------|
| `git add <文件名>` | 添加单个文件 | `git add README.md` |
| `git add .` | 添加当前目录所有改动（新文件+修改+删除） | 最常用 |
| `git add -A` | 添加整个仓库所有改动（含上级目录） | 全量添加 |
| `git add -p` | 交互式按块添加（高级，后续会讲） | 精细控制 |

**实操示例**：
```bash
# 添加README.md到暂存区
git add README.md

# 再次查看状态
git status
```

**终端输出**：
```
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
```

**解读**：文件变绿了，表示已进入"备餐盘"（暂存区），等待提交。

**常见误区**：
- ❌ 忘记 `add` 直接 `commit` —— 会提示 "nothing to commit"
- ❌ `git add .` 会添加所有文件，包括临时文件、日志等（所以要配合 `.gitignore`，见终章）

---

## 5. git commit —— 把菜存进冰箱（生成版本）

**作用**：将暂存区的所有改动永久保存到仓库，生成一个唯一的 commit ID（哈希值）。

**一句话类比**：把备餐盘里的菜下锅炒好，装盒放进冰箱，并在菜谱上记录这道菜的做法。

**常用参数**：

| 参数 | 作用 | 典型用法 |
|------|------|----------|
| `git commit -m "消息"` | 直接带提交信息（最常用） | `git commit -m "初始化项目"` |
| `git commit -a -m "消息"` | 跳过 `add`，直接提交所有已跟踪文件的修改 | 适合快速提交 |
| `git commit --amend` | 修改最近一次提交（修正消息或漏文件） | 后续章节详解 |
| `git commit -m "标题" -m "详细描述"` | 多行提交信息 | 规范项目常用 |

**实操示例**：
```bash
# 提交暂存区的内容
git commit -m "初始化项目：添加README"

# 查看提交历史
git log --oneline
```

**终端输出**：
```
[main (root-commit) a1b2c3d] 初始化项目：添加README
 1 file changed, 1 insertion(+)
 create mode 100644 README.md

# git log --oneline 输出：
a1b2c3d (HEAD -> main) 初始化项目：添加README
```

**解读**：
- `a1b2c3d` 是本次commit的短哈希（唯一ID）
- `HEAD -> main` 表示当前指针在 `main` 分支的最新提交上
- "1 file changed, 1 insertion" 表示1个文件变化，新增1行

**常见误区**：
- ❌ 不写 `-m` 会弹编辑器（Vi/Vim），新手可能卡住。用 `-m` 是最稳妥的
- ❌ 提交信息写得太随意（如 "fix"、"update"）—— 团队协作时会被嫌弃，建议用"动词+对象"格式，如 "修复登录页按钮样式"

## 6. 完整工作流实战演练

**场景**：从零开始，创建项目，写代码，提交两个版本。

```bash
# 1. 初始化
mkdir project-demo && cd project-demo
git init

# 2. 第一个文件
echo "# Hello Git" > index.html
git add index.html
git commit -m "创建首页HTML"

# 3. 修改文件
echo "<h1>Hello Git</h1>" >> index.html   # 追加内容
git status   # 看到 modified: index.html (红色)

# 4. 暂存并提交
git add index.html
git commit -m "完善首页内容"

# 5. 查看所有提交记录
git log --oneline --graph
```

**最终输出**：
```
* b2c3d4e (HEAD -> main) 完善首页内容
* a1b2c3d 创建首页HTML
```

## 7. 理解文件生命周期（状态流转图）

```
           ┌─────────────┐
           │  未跟踪      │  (新建文件)
           └──────┬──────┘
                  │ git add
                  ↓
           ┌─────────────┐
           │  已暂存      │  (Staged)
           └──────┬──────┘
                  │ git commit
                  ↓
           ┌─────────────┐
           │  已提交      │  (Committed, 安全保存)
           └──────┬──────┘
                  │ 编辑文件
                  ↓
           ┌─────────────┐
           │  已修改      │  (Modified, 红色)
           └──────┬──────┘
                  │ git add (再次回到暂存)
                  └────────┐
                           ↓ (循环)
```

## 🧠 本章小结

- `git init` 建仓库（搭厨房）
- `git status` 随时查看状态（巡视灶台/备餐盘/冰箱）
- `git add` 将改动加入暂存区（案板→备餐盘）
- `git commit` 将暂存区保存为版本（备餐盘→冰箱）
- 核心铁律：**任何有价值的改动，必须走完 add → commit 两步才能安全存档**
