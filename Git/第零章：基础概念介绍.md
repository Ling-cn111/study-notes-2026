# 第零章：基础概念介绍

## 📖 概述
本章不敲一行命令，但它是后续所有操作的**认知基石**。我们将搞懂3个问题：
1. 为什么非学版本管理不可？
2. Git是谁？它凭什么成为行业标准？
3. Git的核心模型（工作区/暂存区/仓库）到底怎么理解？

---

## 1. 版本管理：为什么你需要它？

**一句话作用**：记录文件随时间变化的每一步，让你能随时回到任何历史状态，并支持多人并行修改。

**生活类比**：写毕业论文时，你手动复制出 `论文_终版.doc`、`论文_终版_导师修改.doc`、`论文_终版_再也不改了.doc`……这就是“手动版本管理”。它的痛点：
- 找旧内容要翻半天文件夹
- 忘了哪个是最终版
- 两人同时修改会互相覆盖

**Git 解决的就是这些问题**，而且做得极其优雅。

---

## 2. Git 的历史与适用场景

- **诞生**：Linux 之父 Linus Torvalds 在 2005 年为了管理 Linux 内核源码而创造。他讨厌当时商用的版本控制系统，于是两周内写出了 Git 原型。
- **核心特点**：
  - **分布式**：每个人本地都有完整仓库，不依赖中央服务器
  - **性能极强**：Linux 内核源码几万文件，操作依然毫秒级
  - **内容寻址**：用 SHA-1 哈希值（如 `e6a9e...`）来唯一标识每一次文件状态

**适用场景**：
- 个人开发（备份、实验性修改）
- 团队协作（几十人并行开发）
- 开源项目（GitHub/GitLab 上百万项目都在用）

---

## 3. Git 的三层存储结构（重中之重）

这是理解所有 Git 命令的**钥匙**。我们把 Git 仓库想象成一个**厨房**：

| 概念 | 厨房类比 | 技术定义 |
|------|----------|----------|
| **工作区 (Working Directory)** | 灶台/案板 —— 你正在切菜、炒菜的地方 | 你电脑上能直接看到和编辑的文件目录 |
| **暂存区 (Staging Area / Index)** | 备餐盘 —— 你挑好、洗净、切好，准备下锅的配料 | 一个临时存放改动清单的地方，记录下次要提交哪些文件 |
| **本地仓库 (Repository / .git)** | 冰箱 + 菜谱本 —— 已做好的成品菜（历史记录） | `.git` 隐藏目录，存着所有版本的永久快照 |

**工作流循环**：
```
工作区 →（git add）→ 暂存区 →（git commit）→ 仓库
```

**ASCII 示意图**：
```
+-------------+     git add     +-------------+     git commit     +-------------+
|  工作区      | —————————————→ |  暂存区     | ———————————————→ |  本地仓库   |
| (灶台/案板)  |                 | (备餐盘)     |                    | (冰箱+菜谱) |
+-------------+                 +-------------+                    +-------------+
     ↑                                                                   ↓
     └──────────────────── git checkout / restore ────────────────────────┘
```

---

## 4. Git 如何存储数据？（极简底层）

**关键认知**：Git 存的是**快照（Snapshots）**，而不是差异（Differences）。

- 每次 `commit`，Git 会拍下所有文件的**完整状态**，并生成一个 40 位的哈希值（如 `f1e2d3...`）作为该版本的唯一 ID。
- 如果文件没变化，Git 不会重复存储，而是链接到之前的相同文件（节省空间）。
- 三个对象类型：
  - **Blob**：文件内容
  - **Tree**：目录结构（文件名 + 文件引用）
  - **Commit**：作者、时间、父 commit 指针、Tree 引用

**类比**：就像你每次拍照都存一张完整照片，但连续拍同一个场景时，只记录变化的部分（但 Git 的抽象更优雅）。

---

## 5. 三个核心区域的状态流转

| 文件状态 | 含义 | 对应区域 |
|----------|------|----------|
| **未跟踪 (Untracked)** | 新文件，Git 从未见过 | 仅在工作区 |
| **已修改 (Modified)** | 跟踪的文件被改了，但没进暂存区 | 工作区 |
| **已暂存 (Staged)** | 改动已放入备餐盘，等待提交 | 暂存区 |
| **已提交 (Committed)** | 改动已安全存入仓库 | 仓库 |

查看状态的命令（下章会细讲）：`git status` 会清晰显示这些状态。

---

## 🧠 本章小结

- 版本管理 = 时间机器 + 协作平台
- Git 是分布式、基于快照的版本控制系统
- 永远记住 **工作区 → 暂存区 → 仓库** 这个流向
- 任何操作只要没 `commit`，都还有后悔药
