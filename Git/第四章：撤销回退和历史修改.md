# 第四章：撤销回退和历史修改

## 📖 概述
本章目标：**精准控制代码历史**，在不同场景下选择正确的撤销方式。你将学会：
- `reset` 三种模式（`--soft` / `--mixed` / `--hard`）的本质区别
- `revert` 安全撤销已推送的提交
- `restore` 精确恢复工作区/暂存区的文件
- `log` / `diff` / `blame` 等高级历史查看工具

---

## 1. 撤销场景总览（先看菜谱，再动刀）

| 你的需求 | 推荐命令 | 风险等级 |
|----------|----------|----------|
| 撤销工作区的修改（还没add） | `git restore <文件>` | 🟢 安全 |
| 撤销暂存区的添加（已add但未commit） | `git restore --staged <文件>` | 🟢 安全 |
| 修改最近一次commit（消息或漏文件） | `git commit --amend` | 🟡 中等（已推送则危险） |
| 彻底回退到某个历史版本（本地未推送） | `git reset --hard <目标>` | 🔴 危险（丢失改动） |
| 回退但保留工作区改动 | `git reset --soft <目标>` | 🟡 中等 |
| 安全撤销已推送的提交（不改变历史） | `git revert <提交>` | 🟢 最安全 |
| 找回意外丢失的提交 | `git reflog` + `reset/revert` | 🟡 需谨慎 |

## 2. git reset —— 移动"时间指针"（三种模式）

**作用**：将当前分支的 `HEAD` 指向指定的提交，并根据模式决定是否重置暂存区和工作区。

**一句话类比**：你有一台"时光机"——可以选择只转动大脑（--soft）、只清空备餐盘（--mixed）、或者连灶台一起清空（--hard）。

### 核心概念：Git的三棵树

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  HEAD       │     │  暂存区     │     │  工作区     │
│  (历史指针) │     │  (Index)    │     │  (Working)  │
└─────────────┘     └─────────────┘     └─────────────┘
     ↑                    ↑                    ↑
   --soft 停止         --mixed 停止         --hard 停止
```

### 三种模式对比表

| 模式 | HEAD移动 | 暂存区重置 | 工作区重置 | 丢失改动？ | 典型场景 |
|------|----------|------------|------------|------------|----------|
| `--soft` | ✅ 移动 | ❌ 保留 | ❌ 保留 | 🟢 不丢失 | 想合并多次commit后再提交 |
| `--mixed` (默认) | ✅ 移动 | ✅ 重置 | ❌ 保留 | 🟡 工作区改动保留 | 撤销add，回到未暂存状态 |
| `--hard` | ✅ 移动 | ✅ 重置 | ✅ 重置 | 🔴 永久丢失 | 彻底抛弃所有改动 |

### 实操演示（用提交历史理解）

先创建几个提交作为实验对象：
```bash
# 创建3个提交
echo "v1" > version.txt
git add version.txt
git commit -m "v1"

echo "v2" >> version.txt
git commit -am "v2"   # -am = add + commit

echo "v3" >> version.txt
git commit -am "v3"

# 查看历史（3个提交）
git log --oneline
# 输出：
# c3d4e5f (HEAD -> main) v3
# b2c3d4e v2
# a1b2c3d v1
```

### 模式一：`git reset --soft <目标>`（只动HEAD）

**作用**：只回退HEAD指针，暂存区和工作区保持原样。

```bash
# 回退到 v2，但保留暂存区和工作区
git reset --soft b2c3d4e

# 查看状态
git status
# 输出：Changes to be committed: (v3的改动还在暂存区)
#         modified:   version.txt

# 查看文件内容（v3还在！）
cat version.txt
# v1
# v2
# v3
```

**使用场景**：想合并最近两次提交。比如你已经提交了 `v2` 和 `v3`，想合成一个。
```bash
git reset --soft HEAD~2   # 回退2个提交
git commit -m "合并v2和v3为一个提交"
```

### 模式二：`git reset --mixed <目标>`（HEAD + 暂存区）

**作用**：回退HEAD，并将暂存区重置为目标提交的状态，但工作区保持不变。

```bash
# 回退到 v2（默认就是 --mixed）
git reset b2c3d4e   # 等价于 git reset --mixed b2c3d4e

# 查看状态
git status
# 输出：Changes not staged for commit: (v3的改动在工作区)
#         modified:   version.txt

# 查看文件内容（v3还在工作区）
cat version.txt
# v1
# v2
# v3
```

**使用场景**：撤销 `git add`，让文件回到未暂存状态。
```bash
git add .          # 不小心add了所有文件
git reset          # 撤销暂存（等于 git reset --mixed HEAD）
```

### 模式三：`git reset --hard <目标>`（全部重置）

**作用**：回退HEAD，并重置暂存区和工作区到目标提交状态（**会丢失所有未提交的改动**）。

```bash
# 彻底回退到 v2（v3的改动永久丢失！）
git reset --hard b2c3d4e

# 查看文件内容（v3已经没了）
cat version.txt
# v1
# v2

# 查看日志（v3消失）
git log --oneline
# b2c3d4e (HEAD -> main) v2
# a1b2c3d v1
```

**⚠️ 危险警告**：
- `--hard` 会永久删除工作区的未提交改动（不可恢复！除非用 `reflog`）
- 如果已经 `push` 到远程，`--hard` 后无法直接 `push`（需要强制推送，更危险）

**安全使用场景**：
- ✅ 本地实验分支，完全想抛弃所有改动
- ✅ 想彻底回退到某个早期版本（确认不需要中间改动）
- ❌ **绝不要在已推送的公共分支上使用**

### reset 常用参数速查

| 参数 | 完整形式 | 典型用法 |
|------|----------|----------|
| `HEAD~1` | 回退1个提交 | `git reset --soft HEAD~1` |
| `HEAD~3` | 回退3个提交 | `git reset --hard HEAD~3` |
| `<commit-hash>` | 回退到指定提交 | `git reset --mixed a1b2c3d` |
| `--` | 撤销暂存区指定文件 | `git reset -- file.txt`（等价于 `git restore --staged`） |

## 3. git revert —— 安全撤销（不改变历史）

**作用**：创建一个**新的提交**，该提交的改动是"撤销指定提交"的逆向补丁。

**一句话类比**：不是坐时光机回去改历史，而是在历史后面**新加一条记录**说"我反悔了第X次提交"。

### reset vs revert（核心差异）

| | **reset** | **revert** |
|--|-----------|------------|
| 改变历史 | ✅ 重写历史（移除提交） | ❌ 保留所有历史（追加新提交） |
| 安全性 | 🟡 本地安全，远程危险 | 🟢 任何时候都安全 |
| 已推送分支 | ❌ 禁止使用（除非强制推送） | ✅ 推荐使用 |
| 多人协作 | 🔴 会让队友历史混乱 | 🟢 队友正常pull即可 |

**实操示例**：
```bash
# 假设历史如下（v1 -> v2 -> v3）
git log --oneline
# c3d4e5f (HEAD -> main) v3
# b2c3d4e v2
# a1b2c3d v1

# 撤销 v2 的改动（注意：是中间那个提交）
git revert b2c3d4e

# Git会弹出编辑器让你写提交信息（默认 "Revert 'v2'"）
# 保存退出后，自动生成新的提交
```

**终端输出**：
```
[main a1b2c3d] Revert "v2"
 1 file changed, 1 deletion(-)
```

**新历史**：
```
c3d4e5f v3
b2c3d4e v2
a1b2c3d v1
e4f5g6h (HEAD -> main) Revert "v2"  ← 新提交，撤销了v2的改动
```

**解读**：`v2` 的改动被"反向应用"了，但 `v2` 这个提交依然存在。如果以后需要可以再恢复。

**常用参数**：
- `git revert HEAD`：撤销最近一次提交
- `git revert HEAD~2..HEAD`：撤销最近3次提交（会逐个创建revert提交）
- `git revert -n <提交>`：只暂存改动，不自动提交（可以再调整）

**常见误区**：
- ❌ 认为 `revert` 会删除历史提交（不会，它只是追加新提交）
- ❌ 用 `reset` 处理已推送的提交（应该用 `revert`）

## 4. git restore —— 精确恢复文件

**作用**：恢复工作区或暂存区的指定文件到某个状态（Git 2.23+ 新增，替代部分 `checkout` 功能）。

**一句话类比**：不是整体回退，而是**只恢复某一道菜**到之前的味道，其他菜保持不变。

**常用参数**：

| 命令 | 作用 | 典型用法 |
|------|------|----------|
| `git restore <文件>` | 丢弃工作区的修改（回到上次提交的状态） | `git restore README.md` |
| `git restore --staged <文件>` | 将文件从暂存区移除（但保留工作区改动） | `git restore --staged README.md` |
| `git restore --source=<提交> <文件>` | 从指定提交恢复文件 | `git restore --source=a1b2c3d hello.txt` |
| `git restore -s <提交> -SW <文件>` | 同时恢复暂存区和工作区 | `git restore -s HEAD~1 -SW file.txt` |

### 场景一：撤销工作区的修改（还没add）

```bash
# 修改了 README.md 但还没 add
echo "错误的内容" >> README.md

# 查看修改
git diff README.md   # 看到改动

# 丢弃工作区修改（回到上次commit的状态）
git restore README.md

# 再次查看（已恢复）
cat README.md        # 回到了修改前的内容
```

### 场景二：撤销暂存区的添加（已add但未commit）

```bash
# 修改并添加
echo "新内容" >> README.md
git add README.md
git status           # 显示 Changes to be committed

# 从暂存区移除（但保留工作区的修改）
git restore --staged README.md

# 查看状态（回到未暂存状态）
git status
# 输出：Changes not staged for commit
```

### 场景三：从历史提交恢复文件

```bash
# 查看历史
git log --oneline
# a1b2c3d 删除了一些重要内容

# 从 a1b2c3d 恢复某个文件
git restore --source=a1b2c3d deleted-file.txt

# 此时文件被恢复到工作区（需要 git add + commit 保存）
```

**restore vs checkout（旧方式）**：
- ❌ 旧：`git checkout -- file.txt`（容易和切换分支混淆）
- ✅ 新：`git restore file.txt`（职责清晰）

## 5. git commit --amend —— 修改最后一次提交

**作用**：修改最近一次提交的**提交信息**或**追加遗漏的文件**（本质是创建新提交替换旧提交）。

**一句话类比**：菜已经装盒放进冰箱了，但发现盒子上标签写错了，或者少放了片香菜——你换了个新盒子重新放进去。

**使用场景**：
- 提交信息有错别字
- 忘记 `add` 某个文件
- 想合并最新的改动到上次提交

### 场景一：修改提交信息

```bash
# 最近一次提交信息有错
git commit -m "修护bug"   # 应该是"修复"

# 修改最近一次提交的信息
git commit --amend -m "修复bug"
```

### 场景二：追加文件到最近一次提交

```bash
# 提交了 readme.md，但忘记提交 config.js
git add README.md
git commit -m "添加文档和配置"

# 发现忘了 config.js
git add config.js
git commit --amend --no-edit   # --no-edit 保持原提交信息
```

**终端输出**：
```
[main a1b2c3d] 添加文档和配置
 Date: Wed Jul 23 10:00:00 2026 +0800
 2 files changed, 10 insertions(+), 0 deletions(-)
 create mode 100644 config.js
```

**重要警告**：
- ✅ 本地未推送的提交 → 安全使用
- ❌ 已推送到远程的提交 → **不要用 `--amend`**（会改变历史，导致队友冲突）

## 6. 高级历史查看工具

### git log —— 查看提交历史

```bash
# 标准格式
git log

# 精简一行显示
git log --oneline

# 图形化显示分支结构
git log --oneline --graph --all

# 查看最近2条提交
git log -2

# 查看某个文件的提交历史
git log --follow -- README.md

# 搜索包含"fix"的提交信息
git log --grep="fix"

# 查看某作者的所有提交
git log --author="张三"
```

### git diff —— 查看改动差异

```bash
# 工作区 vs 暂存区（未暂存的改动）
git diff

# 暂存区 vs 最近提交（已暂存但未提交的）
git diff --staged

# 工作区 vs 最近提交（所有未提交的改动）
git diff HEAD

# 两个提交之间的差异
git diff a1b2c3d..e4f5g6h

# 两个分支的差异
git diff main..feature
```

### git blame —— 谁动了我的代码？

```bash
# 查看每一行最后是谁修改的
git blame README.md

# 查看某几行（-L 起始行,结束行）
git blame -L 10,20 README.md

# 显示修改时间和作者
git blame -e README.md
```

**终端输出示例**：
```
a1b2c3d (张三 2026-07-20 10:00:00 +0800 1) # 项目简介
e4f5g6h (李四 2026-07-21 14:30:00 +0800 2) ## 安装指南
a1b2c3d (张三 2026-07-20 10:00:00 +0800 3) 执行 `npm install`
```

## 7. 找回丢失的提交（git reflog）

**作用**：记录所有HEAD的移动历史，即使 `reset --hard` 删除了提交，也能通过 `reflog` 找回。

**一句话类比**：你的"时光机"有一个日志，记录了每一次穿梭的时间点，即使迷失也能根据日志回到过去。

**实操示例**（恢复被 `reset --hard` 删除的提交）：

```bash
# 1. 误操作：删除了最新的提交
git reset --hard HEAD~1
# 提交不见了

# 2. 查看 reflog（显示所有HEAD移动记录）
git reflog
# 输出：
# c3d4e5f (HEAD -> main) HEAD@{0}: reset: moving to HEAD~1
# e4f5g6h HEAD@{1}: commit: v3  ← 这是被删除的提交
# b2c3d4e HEAD@{2}: commit: v2
# a1b2c3d HEAD@{3}: commit: v1

# 3. 恢复被删除的提交
git reset --hard e4f5g6h   # 或 git reset --hard HEAD@{1}

# 提交回来了！
```

**reflog 的生命周期**：
- 默认保留90天（可配置）
- 只记录本地操作，不推送到远程

## 🧠 本章小结（选择指南）

**决策树：我要撤销什么？**

```
1. 工作区的文件改动（还没add）
   → git restore <文件>

2. 已暂存但未提交（已add）
   → git restore --staged <文件>  (取消暂存)
   → 或 git reset HEAD <文件>     (旧方式)

3. 已提交但未推送
   → git commit --amend            (修改最近一次)
   → git reset --soft HEAD~1       (合并多个提交)
   → git reset --hard <目标>       (彻底抛弃)

4. 已推送到远程
   → git revert <提交>             (安全撤销)
   → ❌ 不要用 reset

5. 误删了提交
   → git reflog + git reset/revert
```
