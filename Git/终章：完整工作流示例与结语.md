# 终章：完整工作流示例与结语

## 📖 概述
本章目标：**完成一个完整的项目开发周期**，从初始化到功能开发、协作、发布、回滚，所有步骤都配有真实命令和输出。最后给出**最佳实践总结**和**告别语**。

---

## 1. 综合场景演练（完整项目周期）

**场景设定**：你和小李两人协作开发一个名为 `todo-app` 的待办事项应用。你们使用 GitHub 托管代码，采用 **GitHub Flow** 分支策略。

### 阶段一：项目初始化（第零章 + 第一章）

```bash
# 1. 创建项目目录并初始化
mkdir todo-app
cd todo-app
git init

# 2. 创建 .gitignore（第五章）
cat > .gitignore << 'EOF'
node_modules/
.env
*.log
.DS_Store
EOF

# 3. 创建项目文件
echo "# Todo App" > README.md
echo "console.log('Hello Todo');" > index.js

# 4. 首次提交
git add .
git commit -m "初始化项目：添加 README 和基础代码"

# 5. 在 GitHub 创建空仓库（网页操作）
# 仓库名：todo-app

# 6. 关联远程仓库（第二章）
git remote add origin https://github.com/你的用户名/todo-app.git
git push -u origin main
```

**终端输出**：
```
[main (root-commit) a1b2c3d] 初始化项目：添加 README 和基础代码
 3 files changed, 5 insertions(+)
 create mode 100644 .gitignore
 create mode 100644 README.md
 create mode 100644 index.js

Enumerating objects: 5, done.
...
 * [new branch]      main -> main
Branch 'main' set up to track remote branch 'main' from 'origin'.
```

---

### 阶段二：开发新功能（分支 + 开发）（第三章）

**任务**：小李开发"添加待办"功能，你开发"显示待办列表"功能。

#### 小李的工作（feature-add-todo）

```bash
# 1. 从 main 切出功能分支
git switch -c feature-add-todo

# 2. 开发功能（模拟修改代码）
echo "function addTodo() { console.log('添加待办'); }" >> index.js

# 3. 提交
git add index.js
git commit -m "实现添加待办功能"

# 4. 推送远程（便于协作审查）
git push -u origin feature-add-todo
```

#### 你的工作（feature-list-todo）

```bash
# 1. 从 main 切出功能分支
git switch -c feature-list-todo

# 2. 开发功能
echo "function listTodos() { console.log('显示待办列表'); }" >> index.js

# 3. 提交
git add index.js
git commit -m "实现显示待办列表功能"

# 4. 推送远程
git push -u origin feature-list-todo
```

---

### 阶段三：代码审查与合并（merge + 冲突解决）

#### 小李的分支先合并到 main

```bash
# 小李在自己的分支上操作
git switch main
git pull origin main  # 确保 main 最新

# 合并 feature-add-todo
git merge feature-add-todo
# 无冲突，快进合并

# 推送到远程
git push origin main

# 删除本地和远程功能分支
git branch -d feature-add-todo
git push origin --delete feature-add-todo
```

#### 你的分支合并（模拟冲突）

```bash
# 你的分支合并前，先更新 main（小李已经合并了）
git switch main
git pull origin main

# 切回自己的分支，合并 main 的更新（避免最后大冲突）
git switch feature-list-todo
git merge main
# 如果冲突，解决后继续

# 最终合并到 main
git switch main
git merge feature-list-todo
```

**如果发生冲突**（两位开发者都修改了 `index.js` 的同一区域）：

```bash
# Git 提示冲突
git status
# Unmerged paths: both modified: index.js

# 解决冲突（编辑 index.js，保留两人的代码）
# 删除冲突标记 <<<<<<<, =======, >>>>>>>

# 标记已解决
git add index.js

# 完成合并
git commit -m "合并 feature-list-todo，解决冲突"

# 推送
git push origin main

# 清理分支
git branch -d feature-list-todo
git push origin --delete feature-list-todo
```

---

### 阶段四：紧急热修复（hotfix + tag）（第五章）

**场景**：线上版本 `v1.0.0` 发现严重 bug，需要立即修复。

```bash
# 1. 给当前版本打标签（假设已发布）
git tag -a v1.0.0 -m "第一个正式版本"

# 2. 从标签切出热修复分支
git switch -c hotfix-login-bug v1.0.0

# 3. 修复bug（模拟代码修改）
sed -i '' 's/console.log("添加待办")/console.log("添加待办-修复版")/g' index.js

# 4. 提交修复
git add index.js
git commit -m "修复添加待办功能的安全漏洞"

# 5. 测试通过后合并到 main
git switch main
git merge hotfix-login-bug

# 6. 打补丁标签
git tag -a v1.0.1 -m "安全补丁：修复添加待办漏洞"

# 7. 推送所有更新（代码 + 标签）
git push origin main
git push origin --tags

# 8. 删除热修复分支
git branch -d hotfix-login-bug
```

---

### 阶段五：中途切换任务（stash 使用）（第五章）

**场景**：你在 `feature-edit-todo` 分支开发到一半，突然需要紧急切换到 `main` 查看线上问题。

```bash
# 1. 当前在 feature-edit-todo，有未提交的改动
git status
# modified: index.js

# 2. 储藏当前工作
git stash save "WIP: 编辑待办功能（开发中）"

# 3. 切换到 main
git switch main
# 查看问题... 处理完后

# 4. 切回自己的分支
git switch feature-edit-todo

# 5. 恢复工作进度
git stash pop
# 继续开发
```

---

### 阶段六：撤销错误提交（revert 安全回滚）（第四章）

**场景**：你推送了一个有严重 bug 的提交 `e4f5g6h`，但已经推送到了远程，不能强制修改历史。

```bash
# 1. 发现 bug 提交
git log --oneline
# e4f5g6h (HEAD -> main) 添加危险功能  ← 要撤销的提交
# d3c4b5a 正常功能

# 2. 安全撤销（创建反向提交）
git revert e4f5g6h

# 3. Git 打开编辑器，确认撤销信息
# 保存退出后，生成新的 revert 提交

# 4. 推送到远程
git push origin main

# 现在历史中，e4f5g6h 的改动被撤销了，但历史记录完整
```

---

### 阶段七：从历史恢复文件（restore + reflog）（第四章 + 第五章）

**场景**：你不小心删除了 `config.js` 并提交了，后来发现需要恢复。

```bash
# 1. 查看文件被删除的提交
git log --oneline -- config.js
# c3d4e5f 删除配置文件  ← 删除的提交

# 2. 从删除前的提交恢复文件
git log  # 找到删除前的提交哈希 a1b2c3d
git restore --source=a1b2c3d config.js

# 3. 文件恢复到工作区
git add config.js
git commit -m "恢复 config.js"

# 如果不知道哈希，用 reflog 找回
git reflog
# a1b2c3d HEAD@{5}: commit: 添加配置文件
```

## 2. Git 最佳实践总结

### 提交信息规范

**推荐格式**：`<类型>: <简短描述>`

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: 添加用户登录功能` |
| `fix` | Bug修复 | `fix: 修复登录按钮无响应` |
| `docs` | 文档更新 | `docs: 更新README安装说明` |
| `style` | 代码格式（不影响逻辑） | `style: 统一缩进为2空格` |
| `refactor` | 重构（不改变功能） | `refactor: 优化用户验证逻辑` |
| `test` | 测试相关 | `test: 添加登录模块单元测试` |
| `chore` | 构建/工具变动 | `chore: 升级webpack到v5` |

**提交信息三原则**：
1. **标题不超过50字符**
2. **用动词开头**（"添加"而非"添加了"）
3. **一个提交只做一件事**

### 分支命名规范

| 分支类型 | 命名格式 | 示例 |
|----------|----------|------|
| 功能分支 | `feature/描述` | `feature/user-login` |
| 修复分支 | `fix/描述` | `fix/login-timeout` |
| 热修复 | `hotfix/描述` | `hotfix/security-patch` |
| 发布分支 | `release/版本号` | `release/v1.2.0` |

### 日常开发黄金流程

```bash
# 每日开始工作
git switch main
git pull origin main
git switch -c feature/新功能

# 开发过程中
git add .
git commit -m "feat: 完成部分功能"
git push  # 定期推送备份

# 功能完成后，合并前先更新
git switch main
git pull origin main
git switch feature/新功能
git merge main  # 或 git rebase main

# 解决冲突后，合并到 main
git switch main
git merge feature/新功能
git push origin main

# 清理分支
git branch -d feature/新功能
git push origin --delete feature/新功能
```

### 避坑指南（Dos & Don'ts）

| ✅ 应该做 | ❌ 不要做 |
|----------|----------|
| 提交前运行 `git status` 确认改动 | 提交大而全的"巨型提交" |
| 经常 `git pull` 保持同步 | 在公共分支上 `rebase` |
| 用 `revert` 撤销已推送的提交 | 用 `reset --hard` 处理已推送的提交 |
| 项目开始时配置 `.gitignore` | 把密码/密钥提交到仓库 |
| 功能分支推送到远程做备份 | 在 `main` 上直接开发功能 |
| 提交信息写明"为什么改" | 提交信息写 "fix"、"update" |

## 4. 给学习者的最后一句话

🎓 **恭喜你！**

从"版本管理是什么"到"用reflog找回丢失的提交"，你已经走完了绝大多数开发者从未走完的路。你现在掌握的，不仅仅是几个命令，而是一套**严谨的思维模型**：

- 你知道 `reset --soft` 和 `--hard` 之间隔着"不可挽回"的红线
- 你知道 `rebase` 和 `merge` 不是谁优谁劣，而是不同场景下的最佳选择
- 你知道"写得清楚"的提交信息，是对团队最大的尊重

**Git 的哲学是"信任开发者，但不依赖运气"。** 它会给你足够的权力去修改历史，但也要求你承担相应的责任。

从今天起，当你的同事对着 `git reset --hard` 懊恼时，你可以淡定地敲下 `git reflog`，然后说一句：

> "别慌，Git 里没有真正丢失的东西——只要你记得它的哈希。"

**去构建更棒的东西吧。** 有问题时，`git help <命令>` 是你永远的后盾。

| 场景 | 推荐命令 |
|------|----------|
| 从零开始项目 | `git init` + `git remote add origin` |
| 创建新功能分支 | `git switch -c feature/描述` |

| 解决冲突 | 编辑文件 → `git add` → `git commit` |
| 临时切换任务 | `git stash save "WIP"` → 切分支 → `git stash pop` |
| 撤销已推送的提交 | `git revert <提交哈希>` |
| 打版本标签 | `git tag -a v1.0.0 -m "发布信息"` |
| 找回丢失提交 | `git reflog` + `git reset/revert` |
| 从其他分支挑代码 | `git cherry-pick <提交哈希>` |
| 忽略文件 | 创建 `.gitignore` 并提交 |
